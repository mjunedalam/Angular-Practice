# 12. RAG Foundations for Agents

ShopAssist needs the retailer's current returns policy, not a plausible policy remembered from model training. Retrieval-augmented generation, or RAG, supplies relevant source material at request time and asks the model to use it. The important work begins before generation: parsing documents, retaining their structure, identifying current versions and making authorized passages discoverable. A fluent model cannot cite a required passage that the system never found or was not permitted to show it.

RAG is a pipeline with several independently testable responsibilities. We will build the offline collection and the online search/answer path, compare retrieval methods and connect citations to actual evidence. This chapter establishes a quality-controlled baseline; Chapter 13 adds adaptive model-directed retrieval. The difference is control over the search process, not whether the baseline has reranking, freshness checks or evidence verification.

:::analogy Preparing an open-book examination
A student preparing an open-book exam marks section boundaries, keeps an index and knows which edition of each text is current. During the exam, the student finds candidate pages, reads the best ones carefully and cites them in the answer. More books do not help if their pages are torn or the relevant paragraph cannot be found. Where it stops: a citation does not prove that the cited page supports the claim. Software must separately check document access, current validity, citation completeness and support; an answer can cite a real page while misreading it.
:::

## The RAG pipeline

The offline half prepares a collection. Ingestion retrieves approved sources and parsing extracts meaningful content from PDFs, HTML, documents, records or tickets. Chunking creates retrievable units, enrichment adds heading paths, source/version, effective dates, owner and access metadata, and indexing supports query-time lookup. Embeddings are optional representations for semantic search; lexical indexes provide another path. Keep source locators and lineage so index entries can be corrected, deleted and traced.

The online half receives a question and authenticated access context. It retrieves candidates from permitted current records, reranks them if appropriate, selects evidence within an allowance and generates an answer using retained identifiers. The response then passes citation and support checks. An empty or inadequate evidence set can produce insufficient_evidence rather than an invented policy. Each stage returns enough metadata to diagnose where relevant information disappeared or became misleading.

ShopAssist's question "Can I return a used blender?" illustrates the pipeline. The relevant collection may contain a returns section and a warranty section, both current and customer-accessible. Retrieval should identify both; selection should preserve their distinction. The answer may say ordinary returns require unused condition while faulty items follow a separate warranty process, but only if the actual policy supports that conclusion. The model's general retail knowledge must not silently fill a missing eligibility rule.

## Retrieval methods

Dense retrieval represents queries and passages as vectors and ranks their similarity. It can connect paraphrases such as "money back" and "refund" when the embedding model captures that relationship. It may be less reliable for exact identifiers, rare codes or numerical distinctions. Evaluate the embedding model on the domain and language rather than assuming that semantic closeness equals correctness. A highly similar old policy may still be the wrong source for today's decision.

Sparse lexical retrieval, commonly BM25, scores matching terms with attention to factors such as rarity and document length. It is useful for error codes, product names and exact identifiers. Tokenization and analyzers still matter: splitting a code differently can change recall. It may miss a good paraphrase whose wording shares few terms. Dense and lexical retrieval therefore have complementary strengths, but neither is guaranteed to win every query class.

Hybrid retrieval combines the candidate lists. Reciprocal rank fusion, or RRF, sums a rank contribution from each list instead of assuming their raw scores share a scale. For a document at position r, a common contribution is 1/(constant+r). The constant and candidate depth are configuration choices to evaluate. Merge by stable source/chunk identity, deduplicate within each result list and preserve metadata rather than returning anonymous text fragments.

```python
def reciprocal_rank_fusion(lists, constant=60):
    if constant <= 0:
        raise ValueError("constant must be positive")
    scores = {}
    for results in lists:
        seen = set()
        for rank, item_id in enumerate(results, 1):
            if item_id in seen:
                continue
            seen.add(item_id)
            scores[item_id] = scores.get(item_id, 0.0) + (
                1.0 / (constant + rank)
            )
    return sorted(scores, key=lambda key: (-scores[key], key))
```

A PostgreSQL collection can use pgvector for vector similarity alongside an appropriate lexical search implementation. pgvector is an extension supplying vector storage/search, not the complete RAG pipeline or a replacement for entitlement and document-version logic. Its exact index/filter behavior depends on the installed release and configuration. Consult the official repository, measure filtered recall and retain authoritative source metadata in the application.

Filters are not a final cosmetic step. Restrict candidates by tenant, entitlement, language/domain and effective version at the index/query boundary. The agent's service account may access more than the customer may receive. Never retrieve across users and rely only on later output redaction. If a required access feature is unsupported by a chosen index, change the design or use an approved prefiltered collection rather than weakening the information boundary for convenience.

## Chunking and document structure

Chunking defines the unit of evidence. Fixed-size overlapping chunks are easy to implement but can separate a rule from its exception or a table row from its headings. Structure-aware chunks follow sections, list items, table rows and code blocks. Semantic chunking can identify topic shifts with additional computation and variable sizes. Document summaries help select which source to open but do not supply all details required for a specific eligibility decision.

For enterprise policies, a useful starting point is a bounded structural section carrying its heading path. A chunk reading "30 days" without "Unused-item returns" is ambiguous. Prefixing the heading helps both retrieval and interpretation, while the source locator preserves the exact section/version. Keep tables meaningful: row-wise text or intact Markdown can retain column names and units. Scanned sources need verified OCR/parsing; missing cells or distorted values can become downstream factual errors.

Parent-child retrieval indexes smaller passages for precise matching and expands selected children to a parent section for context. It helps recover surrounding exceptions, but the expanded text changes the evidence unit. Recheck the parent's access/version metadata and update the locator accordingly. Do not retain a child-only citation while using facts found elsewhere in its expanded parent. Keep expansion within the token budget and record whether the model saw the child excerpt or full parent representation.

A source can have multiple current representations for different questions. A tiny child may answer an exact code lookup; a parent may explain an operational procedure; a summary may support source selection. Evaluate them against the queries they intend to serve. There is no universally best chunk size or parsing choice. The useful design preserves meaning while allowing the relevant unit to be found, authorized and fitted to a model request.

## Reranking and evidence selection

First-stage retrieval aims to bring relevant candidates into a manageable shortlist. A reranker examines question and passage together or uses another evaluated relevance method to order that shortlist. Its score may not be a calibrated probability. Tune any minimum threshold on representative questions, including cases with no answer in the corpus. A threshold chosen from one library's raw score scale should not be copied blindly to a different model.

Selection then balances coverage and redundancy. Drop repeated representations of the same source, remove superseded versions and preserve distinct passages required for different parts of the question. A short policy clause and its relevant exception may both be needed. Prefer current sources according to their authority/effective dates, expand parents where useful and stop at the context allowance. Returning fewer adequate passages often helps more than filling unused capacity with weak matches.

When nothing meets the relevance and authority contract, return no eligible evidence. The answering stage can clarify the question, identify the gap or escalate. It should not quietly lower the threshold until some text appears. Measure the consequences of omission and inclusion separately: a missing exception can make an answer wrong, while a large irrelevant passage can obscure the correct rule. The context builder from Chapter 8 supplies the final size and provenance checks.

## Citations, provenance, freshness and the knowledge lifecycle

Assign short evidence identifiers, such as E1, mapped to exact source/version/section locators. Require factual claims to name their supporting identifiers. Retain retrieval time, effective version and the selected text representation. The rendered link should open the appropriate source rather than a mutable document homepage if exact historical support matters. A human should be able to inspect the evidence behind a consequential statement without reconstructing a hidden search query.

Three checks must remain distinct. Citation validity asks whether the identifier exists in the selected evidence. Citation completeness asks whether the displayed factual claims have citations. Support asks whether the cited passage actually supports each claim. A simple membership test proves only the first. Deterministic rules can check structured facts, while entailment models or human review may assess broader semantic support with their own error rates. Report the method instead of promising perfect verification.

```python
def check_citation_ids(claims, evidence):
    problems = []
    for claim in claims:
        ids = claim.get("evidence_ids", [])
        if not ids:
            problems.append("claim has no cited evidence")
        for item_id in ids:
            if item_id not in evidence:
                problems.append(f"unknown evidence: {item_id}")
    return problems
```

This complete function checks only structural citation coverage and identifier membership. A supported answer additionally requires the actual claim/source relationship. Render the final answer from accepted structured claims, or check all factual statements in free-form output, so an empty claims list cannot accompany an unchecked answer. For insufficient evidence, use a distinct output contract that does not force the model to invent claims merely to satisfy a nonempty field.

Treat the collection as a data product. Re-index changed sources, record immutable versions and deactivate superseded or revoked passages. Deletion propagates through vectors, lexical entries, caches and retained derived representations according to policy. A current index has a responsible owner, observable freshness lag and restoration procedures. Retrieval of an old policy can be valid for a historical question; the task's effective-date scope should decide, not a universal newest-is-always-right rule.

## RAG failure modes

Diagnose in order. Is the answer in the authorized, relevant corpus? If not, fix the source gap or report insufficiency. If it is, did retrieval find it? If found, did selection include it with the required exception and version? If included, did generation interpret it faithfully? Finally, are citations complete and supportive? This ordering separates corpus, retrieval, ranking, context and generation failures rather than asking a bigger model to compensate for every upstream loss.

A permission leak is not just a relevance defect. A stale source can be perfectly similar and still wrong for the effective date. An uncited claim can be correct by coincidence yet fail the evidence contract. Keep these failure types separate in logs and evaluation. That gives the owner of each pipeline stage a concrete repair and prevents a single answer-quality score from hiding operationally different problems.

## Evaluating retrieval separately

Build a labeled query set with relevant source/chunk identifiers and the proper filters. Recall@k measures the fraction of relevant items retrieved in the first k; hit rate@k asks whether at least one relevant item appeared. MRR and nDCG assess ranking under their label assumptions. Selection precision assesses how much selected evidence is relevant. Generation groundedness, answer correctness and citation support need different labels or judged rubrics.

Handle unanswerable questions deliberately. A query with zero relevant items cannot use the ordinary recall denominator. Evaluate those cases separately for false-positive evidence selection and appropriate abstention. Reject an empty dataset or state clearly that no measurement exists. Otherwise a metric function can divide by zero or produce a misleading average that excludes the very cases where the agent is tempted to invent an answer.

```python
def mean_recall(queries, retrieve, k=10):
    if not queries:
        raise ValueError("empty evaluation set")
    scores = []
    for query in queries:
        relevant = set(query["relevant_ids"])
        if not relevant:
            raise ValueError("score unanswerable queries separately")
        got = set(retrieve(query)[:k])
        scores.append(len(got & relevant) / len(relevant))
    return sum(scores) / len(scores)
```

Use representative real questions with appropriate permission to curate them, not only artificial paraphrases of document titles. Keep identifiers, policies with exceptions, multilingual cases and no-answer examples. Compare parsing, chunks, retrieval and thresholds on the same set. Publish measured charts with their data/method; synthetic bars belong only to clearly labeled teaching illustrations. ## Production lens

An operable RAG system retains source structure, access scope, exact versions and attributable evidence. Retrieval and answer quality have separate metrics; weak evidence produces an honest outcome. Corpus freshness and deletion are observable responsibilities, not background hopes. Citation support checks use stated methods and thresholds. These controls belong in a baseline pipeline before adding adaptive retrieval, because an agentic loop cannot reliably repair a collection whose authority or metadata was lost.

## Interview drills

Explain dense, lexical and hybrid retrieval with one paraphrase and one exact identifier. Describe how parent expansion preserves a rule's context while changing the citation locator. For a wrong answer, trace corpus, retrieval, selection and generation. For citations, distinguish existence, completeness and support. For evaluation, include unanswerable questions. A useful answer names the evidence and access contract rather than merely choosing a vector database.

## Key takeaways

RAG gives the model a governed view of relevant sources. Parsing, chunks and metadata make evidence discoverable; hybrid retrieval and reranking make selection useful; budgets keep context focused. Citations make the chain inspectable but require separate validity, completeness and support checks. Keep the collection current for the task's effective date and measure each stage. These foundations remain necessary when the next chapter gives the model more control over search.
